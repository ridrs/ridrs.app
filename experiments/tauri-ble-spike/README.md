# Tauri 2 + native BLE spike (`experiments/tauri-ble-spike`)

Time-boxed spike for the question in `prompts/experiment-tauri-ble-spike.md`: can ridrs ship Windows,
macOS, iOS and Android apps from one TypeScript code base with Tauri 2 and native Bluetooth LE?
Results, measurements and the recommendation are in [`FINDINGS.md`](FINDINGS.md). The handover
for the Phase 3 implementer is [`HANDOVER-PHASE-3.md`](HANDOVER-PHASE-3.md).

This is an experiment. It lives outside the workspace pipeline (`apps/`, `packages/`, `plugins/`),
is not a pnpm workspace member, and changes nothing outside this folder.

## What is here

```text
src/
├── ble/
│   ├── ipc.ts                 # the slice of Tauri IPC the adapter uses (faked in tests)
│   ├── frame.ts               # binary notification frame: Rust timestamps + payload
│   └── tauri-ble-central.ts   # TauriBleCentral: BleCentral/BleConnection from @ridrs/contracts, unchanged
├── decoders/                  # HR (ported from hr-monitor-osx), Zwift Ride (buttons only), FTMS control point
├── probe/
│   ├── ftms-plugin-probe.ts   # stage 2: the real device-ftms-trainer plugin with a hand-written context
│   ├── core-entry.ts          # stage 3: bundling @ridrs/core for a WebView
│   ├── bundled-discovery.ts   # import.meta.glob plugin discovery (vite.probe-discovery.config.ts)
│   └── shims/                 # measuring-only shims for stage 3 (never used by the app)
├── device-stats.ts            # notifications/s, gaps > 1 s, reconnects, IPC latency percentiles
├── packet-log.ts              # packet log (zwift-packet-capture.log format) in the app data directory
├── selftest.ts                # unattended chain probe (RIDRS_SPIKE_SELFTEST=1)
└── main.ts                    # the one-screen spike UI
src-tauri/
├── src/ble.rs                 # the only native BLE code: thin commands on top of tauri-plugin-blec's handler
├── src/host.rs                # packet log file, keep-awake, selftest flag
├── Info.plist / Entitlements.plist
└── gen/android, gen/apple     # generated by `tauri android init` / `tauri ios init`
tests/                         # Vitest against a fake Tauri IPC
```

Shared ridrs code is imported **read-only** through aliases (`vite.config.ts`, `tsconfig.json`):
`@ridrs/contracts`, `plugins/device-ftms-trainer/parser.ts` and `plugins/device-ftms-trainer/index.ts`.
Nothing is copied.

## Prerequisites

Install the workspace once from the repository root (`pnpm install`), because the aliased ridrs
sources resolve their own dependencies (`zod`, `semver`, `p-retry`) from the workspace.

| Target | Host | Toolchain used for the spike |
|---|---|---|
| all | any | Node 26, npm 11, Rust stable 1.99.1 (`rustup`) |
| macOS | macOS | Xcode 26.3 |
| iOS | macOS | Xcode 26.3, `xcodegen` 2.46, CocoaPods 1.16, Rust target `aarch64-apple-ios`, an Apple development team |
| Android | macOS/Windows/Linux | Android SDK (platform 36/37), NDK 28.2.13676358, JDK (Android Studio JBR), Rust targets `aarch64-linux-android` (+ `armv7`, `i686`, `x86_64` for universal builds) |
| Windows | Windows | MSVC build tools, WebView2, Rust `x86_64-pc-windows-msvc` |

## Build and run

```bash
npm install
npm test                      # Vitest: adapter, decoders, stage 2 probe
npm run typecheck
(cd src-tauri && cargo test)  # Rust: UUID expansion, frame encoding
```

Desktop (macOS/Windows):

```bash
npx tauri dev                 # dev build with hot reload
npx tauri build               # release bundle (.app/.dmg, .msi/.exe)
```

Unattended chain probe on macOS (cold start, IPC round trip, unfiltered and FTMS-filtered scan):

```bash
open --env RIDRS_SPIKE_SELFTEST=1 "src-tauri/target/release/bundle/macos/ridrs BLE spike.app"
cat "$HOME/Library/Application Support/org.ridrs.spike.ble/packet-capture.log"
```

The same probe on mobile. The flag file is consumed on launch:

```bash
# iOS Simulator (no Bluetooth there; proves install, IPC, stage 2)
npx tauri ios build --debug --target aarch64-sim
xcrun simctl install booted "src-tauri/gen/apple/build/arm64-sim/ridrs BLE spike.app"
SIMCTL_CHILD_RIDRS_SPIKE_SELFTEST=1 xcrun simctl launch booted org.ridrs.spike.ble
# Android device or emulator (debug build, so run-as works)
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
adb shell run-as org.ridrs.spike.ble touch selftest.flag
adb shell monkey -p org.ridrs.spike.ble -c android.intent.category.LAUNCHER 1
adb shell run-as org.ridrs.spike.ble cat packet-capture.log
```

Android (environment as used for the spike):

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"
export NDK_HOME="$ANDROID_HOME/ndk/28.2.13676358"
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
npx tauri android build --apk --debug --target aarch64
npx tauri android dev         # on a connected device (USB debugging)
```

iOS (`developmentTeam` is set in `tauri.conf.json`; change it to your own team):

```bash
npx tauri ios build --debug --target aarch64
npx tauri ios dev             # on a connected, unlocked device
```

Stage 3 portability probe (bundles `@ridrs/core` for the browser, plain and with measuring-only shims):

```bash
npx vite build --config vite.probe-core.config.ts
PROBE_SHIMS=1 npx vite build --config vite.probe-core.config.ts
npx vite preview --outDir dist-probe   # open /plain/probe-core.html and /shimmed/probe-core.html
```

## Using the spike UI (manual matrix checks)

1. **Check BLE permissions** (Android runtime permissions; other platforms ask on first scan).
2. **Scan FTMS / HR / Zwift Ride** – no system picker; found devices appear with RSSI and id.
3. **Connect** – subscribes to Indoor Bike Data + control point (FTMS), 0x2A37 (HR), or writes the
   RideOn handshake (Zwift Ride). Each device shows state, notifications/s, gaps > 1 s, max gap,
   reconnect count, last connection loss.
4. **Request control / Set target power 150 W** on an FTMS trainer – the indication response is shown.
5. Switch the trainer off/on: the app reports `connection-lost` and reconnects by the remembered id
   without scanning. **Remembered** devices can also be connected by id after an app restart.
6. **Stage 2** starts the real `device-ftms-trainer` plugin against the same central.
7. **Export packet log** copies the log to Downloads (desktop) or the app's Documents folder (mobile).
